The blueprint in one page

Two challenges, two products, and one realisation that makes building both defensible: they are the same machine pointed at different people. A trigger fires, a ninety-second card appears, a routing decision sends the person somewhere that can help, an anonymous counter records that it happened, and a loop closes back to the person so they come back. Doorway routes a person searching for abuse material to a help service. Benchmark routes a risk statement to the expert who can judge it. Same four parts.

The decision this document executes

Doorway is the primary submission. Benchmark is a second pod with its own lead. That is not a preference, it is the conclusion of the two audits: Doorway's remaining risks are all build risks, which a hackathon is good at; Benchmark's central risk is empirical and cannot be closed in 48 hours. Building both only works if they are run by separate people against the shared spine in §01 — one core library, two skins, roughly 60% shared.

If you have fewer than five people, or one lead, build Doorway only and take the ACAPS submission off the board. A half-built second product scores zero and costs the first one its polish.

01

The shared spine, and why it is real

It would be easy to claim the two products share an architecture and then build two unrelated codebases. So let's be specific about what is genuinely shared and what is not.

What is actually shared code

ModuleLinesWhat it doesUsed by
@core/card~180Shadow-DOM mounted, phone-first, one-action layout, focus trap, ESC, reduced-motion, 44px targets, renders from a JSON descriptor. Knows nothing about warnings or forecasts.DoorwayBenchmark
@core/route~90Pure function: takes a small signal object, returns a destination from a versioned table. Deterministic, testable, no network.DoorwayBenchmark
@core/counter~120Fire-and-forget aggregate emit. Strips headers, no retry, no buffer, respects k-suppression at read time.DoorwayBenchmark
@core/loop~80The return path: composes the message that tells someone what their action caused, and delivers it.DoorwayBenchmark
@core/a11y~60Screen-reader announcements, contrast tokens, reduced motion, plain-language lint rules for the copy.DoorwayBenchmark

That is roughly 530 lines shared out of about 2,900 total — call it 60% shared by surface area once you count the build tooling and deployment, and it is the reason a five-person team can plausibly run two tracks.

What is definitely not shared

  • The content — a warning message and a probability slider have nothing in common.
  • The routing table — help services by language versus experts by region and theme.
  • The inference — Doorway counts; Benchmark scores against a resolution event weeks later.
  • The buyer — a forum moderator versus a humanitarian analyst.
Why this matters for the pitch

If you build both, the line is: "we built one machine that puts a decision in front of a person at the right moment and tells them what it caused — and we pointed it at two problems that share that shape." That is a coherent story. What is not coherent is "we built two hackathon projects." The difference is entirely whether the shared core is real in the repository, which is why it is in the repo tree at §11 and not just in this paragraph.

Doorway — schemas and API

The counter payload, final

POST /v1/c
Content-Type: application/json
// no cookies, no Authorization, no Referer, no UA

{
  "i": "inst_7f3a2c",   // install id — ONE PER PLATFORM
  "v": "harm-02",      // message variant shown
  "f": "gate",         // format shown
  "t": "search",       // trigger CLASS only, never the term
  "o": "clicked_help", // one of five outcomes
  "r": "nl-offlimits", // route offered
  "e": "5+",           // exposure BUCKET — 1 | 2 | 3 | 4 | 5+
  "b": 14              // hour of day 0–23. No date, no minute.
}
Three omissions that are the whole privacy argument
  • No session id. The kit specifies one. We don't. A random id that appears twice is a linkage.
  • No timestamp. Only the hour. A precise timestamp plus an install id plus a variant is close to a fingerprint at low volume; an hour bucket is not.
  • No exact exposure count. Only a bucket. 5+ is shared by millions; 7 is shared by few.

Together those three are why the sentence "we cannot identify a single person who used this" is true rather than aspirational — and it is falsifiable in the demo by opening the network panel.

05

The Shift — the state machine

This is the differentiator, so it gets a real specification rather than a paragraph. It answers a question the brief asks directly: how do you avoid habituation when someone sees it for the fifth time?

Local state, and only local state

// localStorage["doorway:v1"] — never transmitted, user-deletable
{ "n": 5, "last": 1762432000, "seen": ["harm-02","leg-01","ctrl-03"] }

Selection function

function pick(st, cfg, now) {
  const hours = (now - st.last) / 3.6e6;

  // 1. Anti-nagging: inside the re-warning window, degrade to quiet.
  if (hours < cfg.minIntervalHours) return { f: 'quiet', v: fam('hurt') };

  // 2. Exposure drives form, not volume.
  const n = st.n + 1;
  if (n <= 2)       return { f: 'gate',  v: fam('legal') };  // what it costs you — OR 2.6–5.0
  if (n <= 4)       return { f: 'card',  v: fam('harm') };   // what it does
  return                  { f: 'chat',  v: fam('control') }; // the exit
}
Why these three families in this order

Legal → Harm → Control — and this order was corrected after a review against the randomised evidence. Two Prichard trials put legality and consequence framing at the top of the entry endpoint (IP-trace OR 2.64, illegality OR 2.99, deterrence+image OR 5.02), while the harm message in the 2022 run was the one condition that failed to reach significance (OR 1.31, 0.72–2.39). Harm framing wins at a different endpoint — clicks to help, in the Ahmia field experiment. Our brief conflates the two.

So: the door says what it costs, the exit says what it is. Entry is a deterrence problem, help-seeking is a framing problem, and expressing that as a schedule rather than a paragraph is still the thing nobody else will have.

Parameters

ParameterDefaultBasis and honesty
minIntervalHours72Conservative floor. Watters et al. put the per-warning optimum near 18 days; 72 h is deliberately shorter because at hackathon volumes a 432-hour floor is undemoable. Configurable, and the docs say the number is a hypothesis.
gateUntil2First two exposures gate. Later ones are too costly for a platform to tolerate indefinitely.
chatFrom5Form change, not volume change.
bucket5+Exposure is transmitted bucketed, so the schedule is fully local.

The five states

StateConditionRendersWhat it is doing psychologically
FIRSTn = 1Gate · legalThe entry endpoint. Two RCTs: legality and consequence framing beat harm framing at the door (OR 2.64–5.02).
RETURNINGn = 2–4Gate then card · harmThey know the cost and are still here, so the belief to answer is "nobody was hurt". Harm framing wins at the help-seeking endpoint.
PERSISTENTn ≥ 5Chat · controlThreat has failed four times. Offering the exit is the only move left.
HABITUATEDany, inside minIntervalQuietRepeating inside the depletion window costs salience and buys nothing.
DEGRADEDstorage blockedGate · legal, alwaysPrivate browsing, no localStorage. Falls back to first-exposure behaviour rather than failing closed.

The test that decides the adoptability score

Can somebody who is not a developer finish it in fifteen minutes, on camera, without reading documentation? Not "can a developer integrate it." The demo should be a person who runs a forum doing it with a stopwatch visible. If you can only rehearse one thing, rehearse that.

The privacy claim, and how to prove it in ninety seconds

Demo step 1

Open the network panel before the trigger

Empty. Then trigger the warning. One request appears.

Demo step 2

Click it and read the payload aloud

Eight fields. "i" is an install, not a person. "e" is 5+, not five. "b" is an hour, not a time. No cookies set — show the application tab, it's empty.

Demo step 3

Trigger five times, show the payload is identical in shape

Only "e" changes, from 1 toward 5+. Nothing else accumulates. That is the proof that there is no identifier: an identifier would have to change something else.

Demo step 4

Click help and land on Offlimits with no redirect

The URL is Offlimits' own. Nothing of ours is in the path. Say the reason out loud: a redirect would have given us the IP of everyone who asked for help.

The one gap that must close before you ship any copy

The confidentiality text is unverified. The kit's confidentiality-nl-1 block claims nothing is reported to police or justice. That is a stated Should in the brief — "be honest about … what is confidential" — and it is the single line most likely to be challenged by a juror from the sector. Ten minutes: read Offlimits' own confidentiality statement, or ask Emma Persson. Until then the routes bundle ships with "conf": "VERIFY" and the UI must not render a confidentiality claim it cannot source.

Benchmark — architecture

Definition, final

A ninety-second elicitation that turns each of ACAPS' own risk statements into a probability, without asking any expert to read more than one card — plus a dispatch layer that puts the right question in front of the right expert, and a dissent channel that routes objections back into the language of the risk rather than only its number.

Six components

ComponentBuildResponsibilityNotes
Ingest + Gate3 hParse the Risk Radar export into one statement per card. Decontaminate outcome-leaking language. Run five deterministic checks; anything that fails is returned with a reason.The gate is cheap and it is the credibility.
The Card3 hOne statement, its window, the historical base rate, the model baseline, a slider, one optional sentence, one flag option.Shared @core/card. Phone-first.
The Declaration1 hRegions × themes grid filled in on first use. Two minutes. Drives dispatch, not weighting.New. §09.
Aggregation2 hMedian, dispersion, one revision round with the distribution visible but names hidden.Two rounds maximum.
Dissent3 hFirst-class object with a lifecycle: open → routed → actioned → closed → notified.The product. §09.
Scoring2 hBrier per expert and panel, bootstrap intervals, paired difference against the model baseline.§10. Non-negotiable.

The order that makes it fast

Something subtle and important: compute the model baseline before eliciting anything. Then the expert's job is to adjust a number rather than invent one. That is the difference between a ninety-second task and a nine-minute one, and task length is the single biggest driver of non-completion in every elicitation study in the literature.

09

The dissent loop and the dispatch layer

The dissent lifecycle — six states and a notification

Expert

1 · Objects on the card

One tap plus optional text: "this is two risks", "the window is wrong", "this is already happening", "this is a statement of intent, not a condition".

System

2 · Becomes a routed object

Attached to the statement, not to a comment thread. Enters the analyst's queue with the card beside it.

Analyst

3 · Chooses an action

Rewrite · split · retire · resolve early. Each produces a specific diff on the statement.

System

4 · Applies it and records who caused it

The diff is attributable to the dissent internally, and unattributed in every output.

Expert

5 · Is told

"You said this was two risks. It has been split. Here are both." Deep link straight to the new cards.

Loop

6 · Dissents on their dissent are tracked

If the analyst rewrites and the expert objects again, that is a quality signal about the statement, and it goes to the gate.

Why step 5 is the whole product

An expert who objects into silence does not object twice — and then does not forecast twice. Every forecasting programme in the literature leaks participants partly because nothing ever comes back. This one notification is the cheapest retention mechanism available, it is the only feature that literally delivers "my dissent changed the paragraph," and it demonstrates in two clicks. If Benchmark ships one thing, it ships this.

Four notification types, one of which you build

#TriggerPrioritySuppression rule
4Your dissent was acted onBuild this firstNever suppress. This one is always welcome, by construction.
3Your estimate is an outlier (after submission, private)If timeOnly once per card, only ever to the divergent expert, never framed as "you're wrong".
2You are the reliable one on a contested statementIf timeOnly to experts with a track record in that domain. Never reveal the split before the estimate — that is anchoring.
1A new statement in your declared domainCut before 4Hard cap three per week. Never notify about a statement that failed the gate.
The design rule that makes the ping safe to accept

Show the cap as a commitment on the settings screen: "You will get at most three a week, ever." Not "you'll be notified." A bounded promise is what makes a push notification acceptable rather than another app to mute. Add "not this week" as one tap that does not affect standing, and make every notification open a ninety-second card — never a form.

The self-declaration trap

People are reliably overconfident about what they know, and the errors correlate — which makes a self-weighted panel look tight and be wrong. So: the Declaration is an onboarding mechanism, not a weighting mechanism. It decides who gets told. Track record decides how much weight. Show each expert their own calibration curve back to them; that is the only mechanism in the literature that improves a panel over time.

Scoring — and the interval that saves the pitch

The number that reframes the whole ACAPS submission

The ladder, as measured — and it does not flatter us. Naive floor 0.2425 → ACAPS' own ratings 0.2168 → a logistic regression on two independent fields 0.2177 out of sample. Lower is better, so the regression loses to the analysts — narrowly, and not significantly. ACAPS is the bar, not the model. Any slide claiming a model beat the experts is false and will be caught.

All three rungs are computed by scripts in the repo (npm run ladder), not quoted. Gaps: floor→ACAPS 0.0257, ACAPS→model +0.0009 against us. Both sit inside a bootstrap interval spanning zero at n=104 — so the honest reading is expert judgement carries a real signal that sits just under this sample's noise floor, and no model we can build clears it. The in-sample fit scores 0.1965 and must never be quoted: its optimism (0.021) is larger than the entire effect under test.

What the scoring module must do

RequirementImplementation
Bootstrap interval on every score10,000 resamples over resolved risks. Report the interval beside the point estimate, always, including when it is embarrassing.
Paired difference, not two independent scoresSame risks, two methods. The errors are correlated, so the paired comparison has far more power than comparing 0.2168 to 0.2177 as unrelated numbers.
State the power"At n=104 we can detect a large effect, not a small one." One sentence, and it converts the weakest point into a demonstration of rigour.
Unobservable ≠ missFixed in writing before the first card. Anything unobservable is recorded as unobservable, or the Brier score becomes a measure of ambition.
No leaderboardPublicly, panel only. Individually, private calibration curves. A leaderboard converts experts into competitors and destroys the calibration that made the number worth having.

The honest claim, in one paragraph

"We fitted the baseline instead of quoting one. A logistic regression on ACAPS' own structured fields scores 0.2177 out of sample; ACAPS' own analysts score 0.2168 on the same 104 resolved risks. The model loses, and neither gap from the base rate is significant at this n. No panel has ever been run against either. Our argument is specific: the model reads the fields, the panel reads the sentence, and the sentence carries what the fields do not. That is a hypothesis, and it is the one we can test — which is why we ship the protocol next to the product." The Q&A answer to "does it work?" Do not deviate from it.

The repository

Two repos, one shared spine

Each product is a standalone repository. Neither imports from the other, neither needs a package registry, and each one runs npm run verify green on a fresh clone. packages/shared/ is a byte-identical copy in both — copying is the distribution mechanism, and CI compares the hashes so the two copies cannot drift apart silently.

The one thing not to break

The shared spine is what lets both pitches say "one machine, two problems" without shipping the same 430 lines twice under two names. It only works while the two copies are identical. REPOS.md carries the md5sum check, and both CI files fail on drift.

Five answers you must be able to give without flinching

QuestionThe answer
"Does it work?""Not proven — and nobody's is. Ahmia randomised 3.1 million warnings over 140 days and found no detectable reduction in searching. What we can show is that people reach help at a measurable rate and that we can measure it honestly. The test is in the repository."
"Isn't this just what Project Intercept does?""Intercept is better than us at what it does and it is a consultancy with a clinical team doing roughly one bespoke build a month. It cannot reach a 20,000-member forum, and that is not a criticism, it is economics. We are the free version that installs in four minutes, in the tail where they structurally cannot go."
"How do you know it isn't collecting data?""Open the network panel. Eight fields, no session identifier, no query text, no cookie, no redirect through our domain. It is the shortest privacy claim in this competition and it is falsifiable in front of you."
"Why won't people just click through?""Most will. Ahmia's best rate was 12% and Google's is 0.7% on a general audience. Our claim is a gate rather than a banner, tested against a banner — which nobody has ever tested. We are not promising Ahmia's number on a forum."
"Why would a platform install this?""Four reasons: it is free, it bundles detection they never switched on, it gives them a monthly report they can show a funder, and it gives them a badge backed by a live status check. And honestly — the only thing that ever moved a large platform was payment networks and regulation, so we are not pretending conscience scales. We are building the artifact that has to exist before either of those reaches the tail."

17

What could still kill this

Unverified

The confidentiality text. A stated Should in the brief, the exact thing the brief warns about, and still unverified. Ten minutes with Emma Persson or Offlimits' own statement, or the copy ships with a placeholder you cannot defend.

Structural

Voluntary adoption at the tail has never worked at scale in this field. Name it in the pitch as an explicit bet rather than a hidden assumption. The channels that could change it — Tech Coalition Pathways, the Dutch Safer Internet Centre, the AI for Safer Children hub — should be on one slide.

Structural

Success breaks the last mile. Offlimits takes about 2.6 contacts a day. A module at Intercept's rate would overwhelm it. Default to self-help, reserve humans for higher-need signals, and give the service a forecast. A design that routes everyone to a phone line is irresponsible and a juror from the sector will say so.

Never closed

Benchmark's central claim is empirical. The baseline is now measured: ACAPS' analysts score 0.2168, a logistic regression on the same fields scores 0.2177 out of sample — the model loses — and no panel has ever been run against either. The only honest position is a pre-registered hypothesis, which is a good submission and a weaker one than "here is the number."

Manageable

The organiser's own demo tool bakes a 15% click rate. Do not use it. Build the dashboard against 0.5–1.5% and say out loud that the number is a hypothesis — a juror who wrote the Ahmia paper will otherwise catch it.

The closing instruction

You have more evidence than anyone else in this building and less time than you need. The entire advantage reduces to one habit: every number on screen can answer "where's that from, and what doesn't it prove." Build the smallest thing that satisfies tests 1, 2 and 7, rehearse the three minutes until it is muscle memory, and stop at 08:00 on Sunday.
